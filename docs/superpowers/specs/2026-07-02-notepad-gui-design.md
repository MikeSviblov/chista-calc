# Чиста-блокнот (GUI) — дизайн

**Дата:** 2026-07-02
**Статус:** утверждён (дизайн), готов к плану реализации
**Форма:** нативный desktop (Rust egui/eframe), портативный бинарник · **Модель:** живой inline-калькулятор

## 1. Цель и контекст

Оригинальный «Чиста калькулятор» — не CLI, а окно-скретчпад («блокнот, который считает»):
по данным реверса — настройки `StoreText` (помнит текст между запусками), `OnTop`
(поверх окон), геометрия окна, подсказка «Нажмите ENTER для выполнения расчёта», вывод
«Результат = …».

Строим современный эквивалент этого интерфейса — **живой inline-блокнот**: пользователь
пишет строки (выражения, присваивания, функции, циклы), результат каждой строки
показывается сразу справа (парадигма Soulver/Numi). Фронтенд поверх готового ядра
`calc-core` (см. [[chista-calc-repo]] и `docs/superpowers/specs/2026-07-02-modern-calc-design.md`).

### Не-цели v1
- Мобильные платформы; вкладки/несколько документов одновременно; графики/plot;
  темы оформления сверх встроенных светлой/тёмной egui; совместная работа.
- Язык/ядро не меняем, кроме трёх добавлений из §3.

## 2. Крейты и архитектура

Cargo-workspace пополняется бинарным крейтом **`calc-notepad`** (egui/eframe) поверх
`calc-core`. `calc-cli` остаётся без изменений.

```
calc-core   — библиотека-ядро (существует; +3 добавления, §3)
calc-cli    — CLI (без изменений)
calc-notepad — НОВЫЙ: egui-приложение (живой inline-блокнот)
```

Модули `calc-notepad`:
```
main.rs      — точка входа eframe, загрузка настроек, запуск App
app.rs       — NotepadApp: состояние (текст, результаты, настройки), update()
document.rs  — модель документа: текст → построчные результаты (обёртка над calc-core), без egui
editor.rs    — виджет редактора + колонка результатов + подсветка (layouter)
panels.rs    — боковая панель (переменные/функции), панель вывода, тулбар
settings.rs  — загрузка/сохранение настроек и текста (персистентность)
```

Граница: вся логика «текст → результаты» живёт в `document.rs` и опирается только на
`calc-core` (тестируется без egui). Файлы `editor/panels/app` занимаются только отрисовкой
и вводом.

## 3. Изменения в `calc-core` (необходимы для inline)

Три добавления, не ломающие существующий API (CLI продолжает работать):

### 3.1 Построчное вычисление документа
Новый публичный метод фасада:
```rust
pub struct LineResult {
    pub line: usize,            // 1-индексная исходная строка (последней инструкции строки)
    pub outcome: LineOutcome,
}
pub enum LineOutcome {
    Value(Value),               // выражение/присваивание — показать значение
    Defined,                    // fn/alias — «зарегистрировано», без значения
    Error(CalcError),           // ошибка в этой инструкции
}
pub struct DocResult {
    pub lines: Vec<LineResult>, // по одной записи на верхнеуровневую инструкцию
    pub output: String,         // накопленный вывод print/циклов за прогон
}
impl Session {
    pub fn eval_document(&mut self, src: &str) -> DocResult;
}
```
Семантика: парсит весь текст в `Vec<Stmt>`; выполняет инструкции по очереди в одном
`Evaluator`; для каждой пишет `LineResult`. **Ошибка в инструкции не останавливает
остальные** — записывается `Error`, состояние (переменные/функции) до ошибки сохраняется,
выполнение продолжается со следующей инструкции (best-effort). Номер строки берётся из
`pos` инструкции через отображение char-offset → номер строки. Присваивание показывает
присвоенное значение; `fn`/`alias` → `Defined`; выражение → `Value`. Каждый вызов
`eval_document` использует «свежее» состояние сессии (полный ре-eval документа с нуля),
чтобы удалённые строки не оставляли «висящих» переменных.

### 3.2 Перехват вывода `print`
`Evaluator` получает буфер вывода (замена жёсткого `println!`):
```rust
// Evaluator хранит output-накопитель; print пишет туда.
pub fn take_output(&mut self) -> String;  // забрать и очистить
```
CLI сохраняет текущее поведение (после `run` печатает накопленный вывод в stdout — либо
через тонкую обёртку). GUI забирает `output` в `DocResult`.

### 3.3 Снапшот состояния для панелей
```rust
impl Session {
    pub fn variables(&self) -> Vec<(String, Value)>;    // текущие переменные (глобальный скоуп)
    pub fn builtin_names(&self) -> Vec<&'static str>;   // имена встроенных функций (из Registry)
}
```
`Env` получает метод перечисления переменных глобального скоупа; `Registry` — метод
перечисления имён.

## 4. Раскладка UI (egui)

```
┌ Чиста-блокнот ─────────────────────────────────┐
│ [Файл ▾] [Шрифт − +] [☑ поверх окон]           │  тулбар
├──────────────┬───────────────────────┬──────────┤
│ ПЕРЕМЕННЫЕ    │ цена = 1990           │          │
│  цена = 1990  │ штук = 12             │          │
│  штук = 12    │ цена * штук           │ = 23880  │  редактор + колонка
│  x = 1024     │ x = 2^10; x/8         │ = 128    │  результатов
│               │ IntToRoman(2024)      │ = MMXXIV │
│ ФУНКЦИИ ▾     │ Sha256("pwd")         │ = 5e88…  │
│  Sin Cos Sqrt │                       │          │
│  Hash Encrypt │                       │          │
├──────────────┴───────────────────────┴──────────┤
│ вывод print/циклов (сворачиваемая панель)        │
└──────────────────────────────────────────────────┘
```

- **Редактор:** моноширинный `TextEdit` без переноса строк (одна логическая строка =
  одна визуальная строка постоянной высоты). Это даёт простое построчное выравнивание.
- **Колонка результатов:** справа, рисуется вручную по y-смещениям строк (высота строки
  для моноширинного шрифта постоянна; берём число строк и высоту из галлеи). Строка N
  показывает результат инструкции, чья последняя строка = N. Клик по результату —
  копирование в буфер.
- **Левая панель (сворачиваемая):** список текущих переменных `имя = значение` +
  справочник встроенных функций по категориям. Клик по имени функции — вставка в редактор.
- **Нижняя панель (сворачиваемая):** накопленный вывод `print`/циклов.
- **Тулбар:** Файл (Новый/Открыть/Сохранить/Сохранить как), Шрифт −/+, чекбокс «поверх окон».

## 5. Живое вычисление и ошибки

- При изменении текста — debounce ~150 мс, затем `eval_document` всего текста; результаты
  и панель переменных обновляются.
- Ошибочная строка: результат красным + текст ошибки (`CalcError` уже с русскими
  сообщениями и позицией). Остальные строки считаются дальше (best-effort, §3.1).
- Пустые строки и комментарии — без результата.
- Предохранители ядра (глубина выражения/рекурсии, лимит итераций) остаются; при
  срабатывании строка показывает ошибку, приложение не виснет/не падает.

## 6. Персистентность и настройки

- Автосохранение текста блокнота + настроек (размер шрифта, «поверх окон», геометрия
  окна) в конфиг-каталог через crate `directories` (напр. `~/.config/chista-notepad/`),
  восстановление при запуске.
- Явные **Открыть/Сохранить** `.calc`-файлы через нативный диалог (crate `rfd`).
- Автосейв — периодически и при выходе; не мешает явным файлам.

## 7. Подсветка синтаксиса

Кастомный layouter egui: каждую строку токенизируем лексером `calc-core`
(`lexer::tokenize`) и красим числа / строки / имена функций (идентификатор перед `(`) /
операторы / ключевые слова / ошибки. Переиспользуем лексер, без дублирования правил.
Строку с ошибкой лексера подсвечиваем как ошибку (лексер уже возвращает `SyntaxError`).

## 8. Тестирование

- **`calc-core`:** юнит-тесты на `eval_document` (построчные результаты, best-effort после
  ошибки, номера строк, `Defined` для fn/alias), на перехват `print` (`take_output`), на
  `variables()`/`builtin_names()`.
- **`calc-notepad/document.rs`:** тесты модели документа (текст → `DocResult` → строки для
  колонки) без egui.
- **UI-рендер** (egui immediate-mode) юнит-тестами не покрываем; логика отделена от
  отрисовки, поэтому покрытие идёт через `document.rs` и `calc-core`.

## 9. Дистрибуция

- `calc-notepad` — член workspace; `release.yml` дособирает `calc-notepad.exe` (Windows) и
  `calc-notepad` (Linux) и прикладывает к релизу рядом с CLI-бинарниками.
- egui/eframe кросс-собирается под `x86_64-pc-windows-gnu` (бэкенд glow/OpenGL; на Windows
  есть `opengl32`). При проблемах линковки glow — зафиксировать рабочую конфигурацию в
  плане (возможные доп. системные библиотеки mingw).

## 10. Открытые уточнения на этап планирования

- Точный способ построчного выравнивания колонки результатов в egui (ручной рендер по
  галлее vs. пер-строчные виджеты) — выбрать при реализации, начав с ручного рендера.
- Дебаунс и стратегия ре-eval (полный ре-eval документа на каждое изменение приемлем для
  типичных объёмов; при больших текстах — оценить).
- Кросс-сборка eframe под windows-gnu: проверить на первом же CI-прогоне GUI-таргета,
  зафиксировать флаги.

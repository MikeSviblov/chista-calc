# Современный эквивалент «Чиста калькулятор 2.0» — дизайн

**Дата:** 2026-07-02
**Статус:** утверждён (дизайн), готов к плану реализации
**Язык:** Rust · **Форма:** ядро-библиотека + CLI

## 1. Цель и контекст

Оригинал — desktop-приложение под Windows (Delphi, движок `TReckoner`, крипта на
DCPcrypt), исходники утеряны. Бинарник распакован эмуляцией UPX-стаба, инвентарь
функций восстановлён — см. `reverse/extracted-inventory.md`.

Строим **современный эквивалент**, а не клон 1:1. Обратная совместимость со старым
синтаксисом и файлами-сценариями **не требуется** (старых файлов у пользователя нет).
Свобода в выборе синтаксиса и API. Приоритет — поддерживаемость.

### Не-цели v1
- GUI / web / TUI (ядро проектируется так, чтобы их можно было надеть позже).
- «Мёртвые» экзотические шифры/хеши (Ice/ThinIce/Ice2, MARS, Misty1, Haval, Cast256) —
  берём только алгоритмы с проверенными крейтами RustCrypto.
- Произвольная точность (bignum).
- Полноценная библиотека календарных дат.

## 2. Архитектура

Cargo-workspace из двух крейтов:

- **`calc-core`** — библиотека, весь движок, без UI-ввода/вывода. Переиспользуема для
  будущих GUI/web/TUI.
- **`calc-cli`** — тонкий бинарник: REPL, запуск скрипт-файлов, разовый `calc "2+2"`.

Модули `calc-core` (одна ответственность на модуль):

```
lexer     — текст → поток токенов (с позициями)
parser    — токены → AST (Pratt-парсер с приоритетами)
ast       — типы узлов дерева
eval      — обход AST, вычисление; исполнение скрипта/циклов
value     — модель значений
env       — области видимости: переменные, польз. функции, псевдонимы
registry  — таблица встроенных функций + разрешение псевдонимов
builtins/ — math, trig, strings, bases, bits, datetime, file, hash, cipher
error     — типы ошибок с позициями
```

Поток данных: `lexer → parser → ast → eval`. `eval` обращается к `env` (пользовательские
имена) и `registry` (встроенные функции).

### Границы модулей
- `registry` — единственная точка регистрации встроенной функции: `(имя, арность,
  замыкание)`. `builtins/*` только поставляют функции в реестр; `eval` не знает про
  конкретные функции, только вызывает реестр по имени.
- `env` хранит стек областей видимости (глобальная + кадры циклов/скриптов); резолвинг
  имени идёт от внутренней области к внешней.
- Крипта (`hash`, `cipher`) изолирована за диспетчером — замена/добавление алгоритма не
  трогает парсер и eval.

## 3. Модель значений

```rust
enum Value {
    Int(i128),
    Float(f64),
    Str(String),
    Bool(bool),
}
```

- **Целые — `i128`.** Точность для систем счисления, римских чисел и битовых операций.
- **Дробные — `f64`.** Арифметика повышает `Int → Float`, где результат дробный или
  участвует Float.
- **Без bignum** (решение). Для калькулятора i128 + double достаточно. Если позже
  понадобится произвольная точность — добавляется как новый вариант `Value` без слома API.
- Строки — UTF-8 `String`. Bool — результат сравнений/логики.

Правила приведения:
- `Int op Int` → `Int`, кроме `/` дающего нецелое и `^` с отрицательной степенью → `Float`.
- Любой `Float` в операции → результат `Float`.
- Битовые операции и функции систем счисления требуют `Int`, иначе `WrongParams`.

## 4. Синтаксис

Современный, чистый. Совместимость со старым синтаксисом не держим.

### Выражения
- Бинарные с приоритетами (от низкого к высокому):
  `||` → `&&` → сравнения (`== != < <= > >=`) → `+ -` → `* / %` → `^` (правоассоц.) →
  унарные (`- !`) → вызов/скобки.
- Скобки `( )`. Вызов функции: `Func(a, b, c)`.

### Литералы
- Числа: `123`, `1.5`, `1e3`, `1.2e-4`; hex `0x1F`, bin `0b1010`, oct `0o17`.
- Строки: `"..."` с экранированием `\n \t \" \\`.
- Булевы: `true`, `false`.
- Римские числа и произвольные базы — **через функции**, не литералы (литералы
  неоднозначны): `RomanToInt("XIV")`, `IntToRoman(14)`, `IntToBase(35, 36)`,
  `BaseToInt("Z", 36)`.

### Комментарии
`# ...` до конца строки.

### Переменные
`x = 2 + 2` — присваивание возвращает значение (можно использовать в выражении).
Использование: `x * 10`.

### Пользовательские функции
Однострочные, тело — одно выражение (решение; циклы — на уровне скрипта):
```
fn f(x) = x^2 + 1
fn hyp(a, b) = Sqrt(a^2 + b^2)
```
Рекурсия разрешена, но ограничена глубиной стека (см. предохранители).

### Псевдонимы
Имя для встроенной или пользовательской функции:
```
alias sq = Pow
alias хеш = Sha256
```

### Циклы и скрипты
Скрипт — последовательность инструкций (по одной на строку или через `;`).
```
while (cond) { ... }
repeat N { ... }
```
- Тело в `{ }` — последовательность инструкций, вводит область видимости.
- Вывод — функция `print(value, ...)`.
- **Предохранитель:** лимит итераций (по умолчанию, напр., 1_000_000) и лимит глубины
  рекурсии. При превышении — ошибка `LoopLimitExceeded` (аналог оригинального «Цикл
  продолжается длительное время»). Лимит настраивается.

## 5. Встроенные функции (~140)

Категории повторяют `reverse/extracted-inventory.md`, имена — чистые (PascalCase).

- **Математика:** `Abs Sqrt Sqr Pow Exp Ln Log Log2 Log10 Floor Ceil Round Trunc Frac
  Sign Min Max Pi E` и др.
- **Тригонометрия:** `Sin Cos Tan Cotan ArcSin ArcCos ArcTan SinH CosH TanH ArcSinH
  ArcCosH ArcTanH DegToRad RadToDeg`.
- **Системы счисления:** `IntToRoman RomanToInt IntToBase BaseToInt IntToHex HexToInt
  IntToBin BinToInt IntToOct OctToInt` (базы 2..36, алфавит `0-9A-Z`).
- **Биты:** `BitTest BitSet BitClear BitToggle And Or Xor Not Shl Shr`.
- **Строки:** `Length Copy Pos Replace Trim TrimLeft TrimRight Upper Lower Ord Chr
  Concat Compare` (учёт регистра — параметром или отдельными вариантами).
- **Дата/время (минимум):** `Now Date Time` + форматирование `FormatDateTime`,
  `FormatFloat` (без полноценного календаря — YAGNI).
- **Файлы:** `FileToStr(path)`, `StrToFile(path, data)`.
- **Хеши:** через диспетчер `Hash("sha256", data)` + удобные алиасы
  `Md5 Sha1 Sha256 Sha384 Sha512 RipeMD160 Crc32 Adler32 Gost Tiger192` — только те,
  что доступны в проверенных крейтах RustCrypto.
- **Шифры:** через диспетчер `Encrypt("aes", key, data)` / `Decrypt("aes", key, data)`
  + алиасы для мейнстрима: AES/Rijndael, DES, DES3(3DES), Blowfish, Twofish, Serpent,
  CAST5, IDEA, TEA. Режим/кодировка вывода (hex/base64) фиксируются и документируются.

### Диспетчер крипты (решение)
Единый вход `Hash(alg, ...)` / `Encrypt(alg, key, data)` вместо ~50 отдельных функций —
поддерживаемее; эргономика сохраняется тонкими обёртками-алиасами. Список поддерживаемых
`alg` — данные, а не код (таблица), добавление алгоритма = одна строка + тест-вектор.

## 6. Ошибки

```rust
enum CalcError {
    SyntaxError { pos, msg },      // «Ожидалось X, но встретилось Y»
    ParserError { pos, msg },
    UnknownVariable { name, pos },
    UnknownFunction { name, pos },
    WrongParams { func, expected, got, pos },
    DivisionByZero { pos },
    RangeError { msg, pos },       // напр. база вне 2..36
    IoError { msg },               // файлы
    LoopLimitExceeded { limit },
}
```

- Каждая ошибка несёт позицию в исходнике, где применимо.
- CLI печатает сообщение + строку с кареткой `^` под позицией.
- **Язык сообщений: русский** (решение). Идентификаторы, имена функций и код — английские.
  Тексты сообщений вынесены в одно место, чтобы позже можно было локализовать.

## 7. Тестирование

- **Юнит-тесты** на каждую встроенную функцию (граничные случаи, типы аргументов).
- **Крипта** — против опубликованных тест-векторов (NIST/RFC) для каждого хеша и шифра.
- **Парсер** — таблица «выражение → ожидаемое значение», включая приоритеты и
  ассоциативность.
- **Property-тесты (proptest):** round-trip `IntToBase/BaseToInt`, `IntToRoman/RomanToInt`,
  `IntToHex/HexToInt` для допустимых диапазонов.
- **Интеграционные:** прогон скрипт-файлов и сверка вывода `print`; проверка ошибок
  (позиция + текст).
- **Предохранители:** тест, что бесконечный цикл ловится лимитом.
